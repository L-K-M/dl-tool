## Goal
Every screen M3 ships passes axe-core with zero serious or critical violations, every shortcut in doc 09
§3.6 works with no pointer event, and the virtualised grid reports `aria-rowcount` as the total row count
rather than the number of rows in the DOM.

## Interface contract

```ts
// web/e2e/a11y.spec.ts
import AxeBuilder from '@axe-core/playwright';

/** Screens that exist at M3. The Search and RSS screens are appended by the milestones that add
 *  them, so doc 13 section 6.2's five-screen list is complete once M4 and M5 land. */
export const SCREENS: { name: string; path: string }[] = [
  { name: 'setup',    path: '/setup' },
  { name: 'login',    path: '/login' },
  { name: 'tasks',    path: '/' },
  { name: 'detail',   path: '/tasks/all' },
  { name: 'settings', path: '/settings/general' },
];

const results = await new AxeBuilder({ page })
  .withTags(['wcag2a', 'wcag2aa', 'wcag21a', 'wcag21aa', 'wcag22aa'])
  .analyze();
const blocking = results.violations.filter((v) => v.impact === 'serious' || v.impact === 'critical');
expect(blocking, JSON.stringify(blocking, null, 2)).toEqual([]);
```

The virtualisation gate, which is the failure mode virtualisation introduces:

```ts
await stubTasks(page, 10_000);
const grid = page.getByRole('grid');
await expect(grid).toHaveAttribute('aria-rowcount', '10000');
expect(await page.getByRole('row').count()).toBeLessThan(200);
```

```ts
// web/e2e/keyboard.spec.ts
/** Every row is exercised with keyboard input only; the spec asserts that no test calls click(). */
export const SHORTCUTS = [
  { keys: 'ArrowDown',    expect: 'focus moves to the next row' },
  { keys: 'ArrowUp',      expect: 'focus moves to the previous row' },
  { keys: 'Home',         expect: 'focus moves to the first row' },
  { keys: 'End',          expect: 'focus moves to the last row' },
  { keys: 'PageDown',     expect: 'focus moves one viewport down' },
  { keys: 'PageUp',       expect: 'focus moves one viewport up' },
  { keys: 'Space',        expect: 'the focused row toggles selection' },
  { keys: 'Control+a',    expect: 'every row in the filter is selected' },
  { keys: 'Enter',        expect: 'the detail pane opens on the focused row' },
  { keys: 'Delete',       expect: 'the remove dialog opens with the delete-files box unticked' },
  { keys: 'Shift+Delete', expect: 'the remove dialog opens with the box ticked' },
  { keys: 'Control+f',    expect: 'the toolbar filter box takes focus' },
  { keys: 'Escape',       expect: 'the selection clears, or the focused dialog closes' },
  { keys: '?',            expect: 'the shortcut cheat-sheet opens' },
];
```

## Steps
1. Edit `web/package.json` to add `@axe-core/playwright` and run `npm install`.
2. Create `web/e2e/a11y.spec.ts`. For each entry of `SCREENS`, sign in where required with `loginAsAdmin`,
   navigate, wait for the screen's main landmark, then run the `AxeBuilder` analysis above.
3. Print each screen's violation count so the Evidence block carries the numbers, and fail on any serious
   or critical violation with the full JSON in the failure message.
4. Add the two dialog screens to the same file by opening the add-task dialog and the folder browser from
   the tasks screen and analysing with the dialog on top, because a focus trap is where modals fail.
5. Add the virtualisation gate exactly as above, and assert `aria-colcount` matches the number of visible
   columns and that exactly one element inside the grid has `tabindex="0"`.
6. Create `web/e2e/keyboard.spec.ts` walking `SHORTCUTS` in order with `page.keyboard` only. Assert first
   that `Tab` from the toolbar reaches the grid, moves through it once, and then leaves it.
7. Assert that typing into the toolbar filter box does not trigger any shortcut, which is the
   `INPUT`/`TEXTAREA`/`isContentEditable` guard of doc 09 §3.6.
8. Assert the live regions announce: the status bar is `aria-live="polite"`, the reconnect banner is
   `role="alert"`, and the settings dirty bar announces its count.
9. Run the verification command and paste its output under `## Evidence`.

## Acceptance criteria
- [ ] axe-core reports zero serious and zero critical violations on all five screens and both dialogs.
- [ ] `aria-rowcount is the total row count` passes with 10 000 stubbed tasks and fewer than 200 DOM rows.
- [ ] Every row of `SHORTCUTS` passes using keyboard input only.
- [ ] `typing in the filter box does not fire a shortcut` passes.
- [ ] Exactly one element inside the grid carries `tabindex="0"` at any time.
