## Goal
`make e2e` builds the SPA into the binary, starts one dl-tool process against a throwaway config directory,
runs the first-run wizard end to end in Chromium, and proves the grid stays under the 8 ms scripting budget
with 10 000 rows.

## Interface contract

```ts
// web/e2e/fixtures.ts
import path from 'node:path';
import os from 'node:os';

/** Wiped and recreated by the e2e:server script on every run. */
export const STATE_DIR = path.join(os.tmpdir(), 'dl-tool-e2e');
export const BASE_URL = 'http://127.0.0.1:8099';
export const ADMIN = { username: 'e2e-admin', password: 'correct horse battery staple' };

/** Reads <STATE_DIR>/setup-token, polling for up to 10 s while the server boots. */
export async function readSetupToken(): Promise<string>;
/** POSTs /api/v1/auth/setup once; a 409 means a previous spec already created the admin. */
export async function ensureAdmin(request: import('@playwright/test').APIRequestContext): Promise<void>;
/** Signs in through the /login form and waits for the grid container. */
export async function loginAsAdmin(page: import('@playwright/test').Page): Promise<void>;
/** Seeds list/sync responses and installs the EventSource fixture before navigation (doc 13 section 6.3). */
export async function stubTasks(page: import('@playwright/test').Page, n: number): Promise<void>;
// Keep tick-delivery and measurement helpers in this fixture module; no production hooks.
```

```ts
// web/playwright.config.ts
export default defineConfig({
  testDir: './e2e',
  fullyParallel: false,
  reporter: [['list']],
  use: { baseURL: BASE_URL, trace: 'on-first-retry' },
  projects: [{ name: 'chromium', use: { ...devices['Desktop Chrome'] } }],
  webServer: {
    command: 'npm run e2e:server',
    url: `${BASE_URL}/healthz`,
    timeout: 180_000,
    reuseExistingServer: false,
    env: {
      DLTOOL_HTTP_ADDR: '127.0.0.1:8099',
      DLTOOL_CONFIG_DIR: STATE_DIR,
      DLTOOL_DB_PATH: path.join(STATE_DIR, 'dl-tool.db'),
      DLTOOL_DATA_ROOTS: path.join(STATE_DIR, 'data'),
      DLTOOL_LOG_FORMAT: 'text',
    },
  },
});
```

`web/package.json` script, one line, run from `web/`:

```json
"e2e:server": "rm -rf \"$DLTOOL_CONFIG_DIR\" && mkdir -p \"$DLTOOL_DATA_ROOTS\" && npm run build && rm -rf ../internal/api/dist && cp -R dist ../internal/api/dist && cd .. && go build -o bin/dl-tool ./cmd/dl-tool && exec ./bin/dl-tool"
```

Version: `@playwright/test@1.62.1` (doc 09 §1).

## Steps
1. Edit `web/package.json` to add `@playwright/test` `1.62.1` and the `e2e:server` script above, then run
   `npm install` to update the lockfile.
2. Create `web/e2e/fixtures.ts` with the interface above. Implement `stubTasks` and its tick helpers
   according to [doc 13 §6.3](../13-testing-and-verification.md#63-grid-update-performance).
   The production transport must already exist through T051; do not implement or bypass it here.
3. Create `web/playwright.config.ts` exactly as above. No engine variable is set: the engines are
   disconnected and nothing in these specs creates a task.
4. Create `web/e2e/setup.spec.ts` with three tests, run in this order in one file:
   `first run creates the admin` navigates to `/`, expects the redirect to `/setup`, fills the token from
   `readSetupToken()` plus `ADMIN`, submits, and expects the app shell;
   `a second setup attempt is rejected` posts `/api/v1/auth/setup` again through `request` and expects
   `409` with `type` `/problems/setup-already-complete`;
   `the grid stays inside the scripting budget` installs `stubTasks(page, 10_000)` before navigation,
   calls `loginAsAdmin(page)` in its own browser context, and runs the workload and measurement contract
   in [doc 13 §6.3](../13-testing-and-verification.md#63-grid-update-performance).
5. Prove the negative control from that contract fails before running the normal performance scenario;
   record the failure output and restored-run output in Evidence. Keep all helpers in the Files table.
6. Run the verification command twice and paste both outputs under `## Evidence`.

## Blocked
**2026-09-15 — shipped UI misses the 8 ms budget; fix needs files outside the Files table.**

The harness is complete and correct: `make e2e` boots the server, all three specs
run, the first two pass, and the performance spec delivers and verifies all ten
update ticks. It then fails the p95 assertion because the shipped update path —
not the fixture — costs ~35–58 ms of scripting per tick at 10 000 rows:

```text
grid perf: 30 changed rows per tick, 10 measured ticks
grid perf deltas (ms): 35.494, 58.174, 37.972, 34.421, 44.537, 38.673, 39.616, 42.196, 42.067, 42.703
grid perf p95: 58.174 ms (budget 8 ms)
```

In-page probe (same payload, timed around the dispatch + the following frame):

```text
tick 2: {"emit":3.5,"raf1":34.9,"raf2":11.4}
tick 3: {"emit":3.5,"raf1":30.5,"raf2":3.1}
tick 4: {"emit":3.7,"raf1":30.6,"raf2":3.3}
```

So the emit/reducer path is ~3.5 ms and the render pass is ~30 ms every tick.
That pass is dominated by O(10 000)-per-notification work outside this task's
Files table:

- `applySync` rebuilds `new Map(state.tasks)` (10k entries) per delta —
  `web/src/store/useTasks.ts`.
- `TaskGrid`'s `useTasks.subscribe` sort-diff scans all 10 000 ids on every
  store change — `web/src/components/TaskGrid/TaskGrid.tsx` (~line 763).
- `Sidebar` runs `selectFilterCounts` + `selectCategoryCounts` +
  `selectTagCounts` (each O(10k); the tag count allocates a `Set` per task) and
  two `[...tasks.values()]` memos per tick — `web/src/components/Shell/Sidebar.tsx`.
- `Toolbar` runs `selectFilterCounts` per tick — `web/src/components/Shell/Toolbar.tsx`.

Fixing it means making per-tick subscriber work O(changed) — e.g. maintain
filter/category/tag counts incrementally inside `applySync`, or memoize the
selectors on changed ids — plus dropping the 10k sort-diff scan. All of those
files are outside the Files table, and the task forbids weakening the 8 ms
budget or the 10 000-row count. This is a plan defect (the shipped shell
misses NFR-001): it needs either a new performance task ahead of T043 or a
Files-table amendment.
