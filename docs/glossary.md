# Glossary

> **Status:** draft
> **Last reviewed:** 2026-09-01
> **Audience:** implementing agent
> **Read this before:** every other document in `docs/`, and every task file under `docs/tasks/`

## Purpose
Define every term of art used across the dl-tool plan, so that a reader who has never seen Synology
Download Station, Torznab or libtorrent can read any document without external lookups. It defines terms
only; it never owns a schema, a table, an endpoint or an env var.

## Scope of this document
- In scope: one-line definitions of protocol, product, engine, plan-process and infrastructure vocabulary.
- Out of scope (lives instead in): the `Engine` Go interface → [`06-download-engines.md`](06-download-engines.md); table columns and enums → [`04-data-model.md`](04-data-model.md); request/response shapes → [`05-api-contract.md`](05-api-contract.md); env vars → [`11-config-reference.md`](11-config-reference.md).

## Terms

| Term | Definition | Where it is used |
|---|---|---|
| Adapter | The Go package that translates between dl-tool's `Engine` interface and one external daemon's own protocol, e.g. `internal/engine/aria2`. One adapter per engine; adapters never talk to each other. | [`06-download-engines.md`](06-download-engines.md) |
| Alternative speed | A second, usually lower, pair of global download/upload rate limits that the 24×7 schedule can switch to per hour cell. Download Station restricts it to BitTorrent tasks; dl-tool applies it to every engine as a second global limit value, because aria2 and yt-dlp have no native alternative-speed concept. | [`06-download-engines.md`](06-download-engines.md), [`09-web-ui-spec.md`](09-web-ui-spec.md) |
| aria2 | The external `aria2c` daemon, driven over JSON-RPC, that dl-tool uses for HTTP, HTTPS, FTP, FTPS, SFTP and Metalink transfers. It supports BitTorrent but dl-tool never routes torrents to it, because it implements neither BEP 52 nor uTP. | [`06-download-engines.md`](06-download-engines.md) |
| Base path | A URL prefix such as `/dl-tool` under which the whole application is served when it sits in a reverse-proxy subfolder. The server must prefix its own links, assets and session-cookie `Path`; the `__Host-` cookie prefix is unusable under a base path because it requires `Path=/`. | [`10-deployment-and-compose.md`](10-deployment-and-compose.md), [`11-config-reference.md`](11-config-reference.md) |
| Bencode | The BitTorrent serialisation format (BEP 3): integers `i42e`, byte strings `4:spam`, lists `l…e`, dictionaries `d…e`. A `.torrent` file is one bencoded dictionary; dl-tool parses it, never writes it. | [`06-download-engines.md`](06-download-engines.md) |
| BEP 52 | The BitTorrent Enhancement Proposal that defines BitTorrent v2: a merkle file tree, per-file piece layers, and a SHA-256 based infohash. Support for it is the reason qBittorrent (libtorrent 2.x) is the BitTorrent engine rather than aria2. | [`06-download-engines.md`](06-download-engines.md), [`decisions/0005-aria2-qbittorrent-ytdlp-engines.md`](decisions/0005-aria2-qbittorrent-ytdlp-engines.md) |
| BitTorrent v2 | The torrent format defined by BEP 52. A v2-only torrent has only a SHA-256 infohash; a hybrid torrent carries both a v1 and a v2 infohash and must resolve to one dl-tool task, not two. | [`04-data-model.md`](04-data-model.md), [`06-download-engines.md`](06-download-engines.md) |
| Cardigann | The YAML indexer-definition format used by Jackett and Prowlarr, originally from `cardigann/cardigann` (Go, MIT, 2016, now dormant). dl-tool's own `dlsearch/v1` format is a deliberate subset of it so definitions can be converted mechanically. | [`07-search-and-indexers.md`](07-search-and-indexers.md) |
| Category | A user-defined label on a task that may carry a default destination path, e.g. `linux-isos`. Categories are global and admin-managed; a task has at most one. | [`04-data-model.md`](04-data-model.md), [`05-api-contract.md`](05-api-contract.md) |
| Control plane | Software that owns the queue, users, destinations, search, rules and UI while delegating the actual byte transfer to separate daemons. dl-tool is a control plane; it contains no BitTorrent, NNTP or hoster-scraping implementation of its own. | [`01-vision-and-scope.md`](01-vision-and-scope.md), [`decisions/0001-control-plane-over-existing-engines.md`](decisions/0001-control-plane-over-existing-engines.md) |
| DHT | Distributed Hash Table (BEP 5): the trackerless peer-discovery network BitTorrent clients use when a magnet link names no tracker. qBittorrent provides it; dl-tool embeds no DHT crawler of its own. | [`06-download-engines.md`](06-download-engines.md) |
| `.dlm` | Synology's "Download Manager" search-module package: a tar.gz containing an `INFO` metadata file plus one PHP file whose name is given by `INFO.module` (usually `search.php`). dl-tool extracts and statically analyses it to produce a definition; it never executes the PHP. | [`07-search-and-indexers.md`](07-search-and-indexers.md) |
| `dlsearch/v1` | dl-tool's own declarative YAML schema for describing a search source that is not a Torznab endpoint, covering RSS, JSON and simple HTML sources. It is data only: no expressions, no scripting, no code execution. | [`07-search-and-indexers.md`](07-search-and-indexers.md) |
| Dry run | Evaluating an RSS rule against stored feed items without creating any task, returning every evaluated item together with a reason code explaining each match and each non-match. | [`08-rss-automation.md`](08-rss-automation.md) |
| EARS | Easy Approach to Requirements Syntax: five fixed requirement sentence templates (ubiquitous, event-driven, state-driven, optional-feature, unwanted behaviour) that force the trigger and the actor into fixed positions. Every `FR-###` in this plan uses one of them. | [`02-requirements.md`](02-requirements.md) |
| Engine | One external download daemon or process that dl-tool drives: aria2, qBittorrent-nox or yt-dlp in v1. dl-tool assumes exclusive control of every engine it is configured with. | [`06-download-engines.md`](06-download-engines.md), [`decisions/0017-exclusive-control-of-engines.md`](decisions/0017-exclusive-control-of-engines.md) |
| Engine reference | The identifier the engine itself assigns to a transfer, stored alongside the engine name as `engine` plus `engine_ref` — an aria2 GID, a qBittorrent infohash or a yt-dlp job id. It is internal and never appears in a dl-tool URL. | [`04-data-model.md`](04-data-model.md), [`06-download-engines.md`](06-download-engines.md) |
| EXDEV | The POSIX error returned by `rename(2)` and `link(2)` when source and destination are on different filesystems. It forces a slow copy-then-delete instead of an instant move, which is why dl-tool mandates a single `/data` mount. | [`10-deployment-and-compose.md`](10-deployment-and-compose.md), [`decisions/0012-single-data-mount.md`](decisions/0012-single-data-mount.md) |
| Feed item | One entry parsed out of an RSS or Atom feed and stored by dl-tool, carrying title, publication date, the extracted download URL and any infohash. Items are retained after matching so rules can be re-run and dry-run against them. | [`08-rss-automation.md`](08-rss-automation.md) |
| Foreign task | A task in an engine that dl-tool did not create, which dl-tool ignores. It never appears in the queue, the grid or an SSE delta, counts toward no quota or concurrency limit, and is never controlled or deleted by dl-tool. There is no setting and no adopt mode. | [`06-download-engines.md`](06-download-engines.md), [`decisions/0017-exclusive-control-of-engines.md`](decisions/0017-exclusive-control-of-engines.md) |
| FR / NFR | Functional Requirement and Non-Functional Requirement. IDs are `FR-001…` and `NFR-001…`, allocated in fixed ranges, immutable once assigned, and referenced by every task file. | [`02-requirements.md`](02-requirements.md) |
| GID (aria2 GID) | aria2's own 16-hex-character identifier for a download, returned by `aria2.addUri` and `aria2.addTorrent` and required by every later call. `aria2.addMetalink` returns an array of GIDs, not one. | [`06-download-engines.md`](06-download-engines.md) |
| Hardlink | A second directory entry pointing at the same inode, so a file appears in two paths without using twice the space. Hardlinks cannot cross filesystems or mounts and cannot be made for directories, so a media library that hardlinks from the download folder needs both paths inside one mount. | [`10-deployment-and-compose.md`](10-deployment-and-compose.md) |
| Huma | The Go HTTP framework layered on chi that dl-tool uses; handlers are declared as Go structs with tags and the OpenAPI 3.1 document is generated from them. The generated spec is committed as `api/openapi.json` and verified in CI. | [`03-architecture.md`](03-architecture.md), [`05-api-contract.md`](05-api-contract.md) |
| Indexer | A configured search source: a Torznab or Newznab endpoint, or a `dlsearch/v1` definition. Indexer IDs are prefixed `idx_`; imported indexers start disabled and record their provenance. | [`07-search-and-indexers.md`](07-search-and-indexers.md) |
| Infohash v1 | The SHA-1 hash of the raw bencoded bytes of a torrent's `info` dictionary, 40 lowercase hex characters. It is the identity of a v1 or hybrid torrent and the value carried by `magnet:?xt=urn:btih:`. | [`04-data-model.md`](04-data-model.md), [`06-download-engines.md`](06-download-engines.md) |
| Infohash v2 | The SHA-256 hash of a BEP 52 torrent's `info` dictionary, 64 lowercase hex characters. A v2 magnet carries it as `xt=urn:btmh:` with a multihash prefix, and a hybrid torrent has both this and a v1 infohash. | [`04-data-model.md`](04-data-model.md), [`06-download-engines.md`](06-download-engines.md) |
| Job | A durable unit of background work stored as a row in the `jobs` table and executed by the in-process worker pool, e.g. an extraction, a move or a notification delivery. There is no external broker and no Redis. | [`03-architecture.md`](03-architecture.md), [`decisions/0015-db-backed-in-process-job-queue.md`](decisions/0015-db-backed-in-process-job-queue.md) |
| Magnet URI | A `magnet:?…` link identifying a torrent without the `.torrent` file, using `xt` for the infohash, `dn` for a display name and `tr` for tracker URLs. Metadata, and therefore the file list and total size, only become known after peers supply it. | [`06-download-engines.md`](06-download-engines.md) |
| Manifest | The result of `POST /tasks/inspect`: the name, total size and file list decoded from a URI or uploaded blob, returned without creating a task so the user can choose files first. | [`05-api-contract.md`](05-api-contract.md) |
| Metainfo | The bencoded dictionary that makes up a `.torrent` file, including the nested `info` dictionary that is hashed to form the infohash. dl-tool parses metainfo purely to inspect and identify torrents. | [`06-download-engines.md`](06-download-engines.md) |
| Metalink | An XML document listing several mirror URLs plus checksums for the same file, standardised as Metalink 4.0 in RFC 5854. aria2 consumes it natively, so dl-tool passes it through rather than parsing it. | [`06-download-engines.md`](06-download-engines.md) |
| Newznab category ID | The numeric category vocabulary shared by Newznab and Torznab: roots 1000 Console, 2000 Movies, 3000 Audio, 4000 PC, 5000 TV, 6000 XXX, 7000 Books, 8000 Other, each with subcategories such as 5040 TV/HD. The `100000+` range is reserved for per-indexer custom categories. | [`07-search-and-indexers.md`](07-search-and-indexers.md) |
| NZB | The XML index file describing where an article set lives on Usenet, consumed by NNTP downloaders. dl-tool v1 does not download NZBs; the term appears only so the `Engine` interface is not designed in a way that precludes v2 support. | [`01-vision-and-scope.md`](01-vision-and-scope.md) |
| PUID / PGID | Container environment variables carrying the numeric user and group id that the process should run as, so files written to a bind mount are owned by the host user. The entrypoint applies them and drops privileges with `su-exec`; the application itself never reads them. | [`10-deployment-and-compose.md`](10-deployment-and-compose.md) |
| rid delta | The update model borrowed from qBittorrent's `sync/maindata`: the client returns the last response id it saw, and the server replies with either only the changed fields or a full snapshot flagged `full_update`. In dl-tool the SSE event id is the rid, so the browser's `Last-Event-ID` header resumes the stream for free. | [`03-architecture.md`](03-architecture.md), [`05-api-contract.md`](05-api-contract.md) |
| RSS rule | A stored, cross-protocol automation rule that matches feed items on title include and exclude terms, an optional episode filter and a set of affected feeds, then creates a task with a chosen destination and category. dl-tool implements this natively and never delegates to qBittorrent's `rss/*` API. | [`08-rss-automation.md`](08-rss-automation.md), [`decisions/0009-native-cross-protocol-rss-rules.md`](decisions/0009-native-cross-protocol-rss-rules.md) |
| Seeding ratio | Uploaded bytes divided by downloaded bytes for a torrent, used as the stop condition for seeding alongside a seeding-time limit. Download Station stops only when both criteria are met; dl-tool deliberately stops when **either** is reached, with no setting to restore the AND. | [`06-download-engines.md`](06-download-engines.md) |
| Session | A server-side login record keyed by an opaque cookie value, with its own row in the database and a TTL. dl-tool has no anonymous mode and no default credentials. | [`12-security-and-threat-model.md`](12-security-and-threat-model.md), [`decisions/0013-mandatory-built-in-authentication.md`](decisions/0013-mandatory-built-in-authentication.md) |
| SSE | Server-Sent Events: a long-lived `text/event-stream` HTTP response over which the server pushes named events. dl-tool exposes one stream at `GET /api/v1/events`; the browser reconnects automatically and resends the last event id. | [`05-api-contract.md`](05-api-contract.md), [`decisions/0006-sse-with-rid-deltas.md`](decisions/0006-sse-with-rid-deltas.md) |
| SSRF | Server-Side Request Forgery: tricking the server into fetching a URL the caller could not reach itself, such as cloud metadata endpoints or RPC ports on the LAN. dl-tool fetches user-supplied URLs constantly, so every outbound fetch is guarded and every redirect hop re-checked against the resolved IP. | [`12-security-and-threat-model.md`](12-security-and-threat-model.md) |
| `sync` | The polling fallback endpoint `GET /api/v1/sync?rid=N`, which returns exactly the same payload as one SSE event. Clients switch to it when the event stream cannot be established. | [`05-api-contract.md`](05-api-contract.md) |
| Task | dl-tool's own record of one download, identified by a `tsk_`-prefixed ULID and owned by a user. It is the unit the API, the grid and the queue operate on, independent of which engine currently carries it. | [`04-data-model.md`](04-data-model.md), [`05-api-contract.md`](05-api-contract.md) |
| Task state | The single normalised lifecycle value on a task: `queued`, `downloading`, `seeding`, `paused`, `checking`, `extracting`, `moving`, `completed`, `error` or `removed`. Every engine's own status vocabulary is mapped onto exactly these ten. | [`04-data-model.md`](04-data-model.md), [`06-download-engines.md`](06-download-engines.md) |
| `thunder://`, `flashget://`, `qqdl://` | Obfuscated links that wrap an ordinary HTTP URL in base64: `thunder` wraps it between `AA` and `ZZ`, `flashget` between `[FLASHGET]` and `[FLASHGET]`, and `qqdl` adds no padding at all. dl-tool decodes them to the plain URL and then routes that URL normally. | [`06-download-engines.md`](06-download-engines.md) |
| Torznab | The torrent-oriented dialect of the Newznab API: one `GET /api` endpoint taking `t=caps`, `t=search`, `t=tvsearch`, `t=movie` and an `apikey`, returning RSS 2.0 with `torznab:attr` elements for seeders, size and category. It is dl-tool's primary search interface, which is what makes Prowlarr, Jackett and bitmagnet work out of the box. | [`07-search-and-indexers.md`](07-search-and-indexers.md), [`decisions/0008-torznab-first-declarative-yaml-second.md`](decisions/0008-torznab-first-declarative-yaml-second.md) |
| ULID | A 26-character Crockford base32 identifier whose leading bits are a millisecond timestamp, so IDs sort chronologically as strings. dl-tool prefixes them by entity, e.g. `tsk_`, `usr_`, `fed_`, `rul_`, `idx_`. | [`14-conventions.md`](14-conventions.md) |
| WAL | SQLite's write-ahead logging journal mode, which lets readers proceed during a write and which persists once set. It does not work over a network filesystem, so dl-tool refuses to start when its database directory is on NFS, CIFS, SMB or FUSE. | [`04-data-model.md`](04-data-model.md), [`17-operations-and-runbook.md`](17-operations-and-runbook.md) |
| Watch folder | A directory that dl-tool scans for dropped `.torrent` files and turns into tasks automatically, optionally deleting the file once loaded. Each watch folder carries its own destination and category defaults. | [`02-requirements.md`](02-requirements.md), [`05-api-contract.md`](05-api-contract.md) |
| Zip-slip | An archive-extraction flaw where an entry name such as `../../etc/cron.d/x` escapes the extraction directory. It applies to zip, tar, rar and 7z alike, so every extracted member path is validated against the target root before any write. | [`12-security-and-threat-model.md`](12-security-and-threat-model.md) |
