## Purpose
Define where code lives, how it is named, how errors and logs are shaped, and how commits and branches are
formed. It does not define product behaviour, test targets or the Definition of Done.

## Scope of this document
- In scope: repository layout, Go package and error conventions, `log/slog` usage, the `task_events.code`
  vocabulary rule, frontend file and data-flow conventions, git branch and commit format, the seven
  repository-wide hard rules, three "how to add X" checklists.
- Out of scope (lives instead in): env vars → [`11-config-reference.md`](11-config-reference.md); DDL and
  enums → [`04-data-model.md`](04-data-model.md); HTTP shapes → [`05-api-contract.md`](05-api-contract.md);
  the `Engine` interface → [`06-download-engines.md`](06-download-engines.md); the `dlsearch/v1` schema →
  [`07-search-and-indexers.md`](07-search-and-indexers.md); screens and i18n plumbing →
  [`09-web-ui-spec.md`](09-web-ui-spec.md); Makefile targets and the Definition of Done → doc 13.

## 1. Repository layout

Create no directory that is not in this tree; the component diagram is in
[`03-architecture.md`](03-architecture.md).

```text
dl-tool/
├── README.md  AGENTS.md  CLAUDE.md  LICENSE  NOTICE  CONTRIBUTING.md
├── Makefile  compose.yaml  compose.dev.yaml  .env.example  Dockerfile  .dockerignore
├── .github/
│   ├── copilot-instructions.md      # Copilot mirror of AGENTS.md
│   └── workflows/                   # ci.yml, release.yml, docs-lint.yml
├── api/openapi.json                 # GENERATED by `make gen`, committed, CI-verified
├── cmd/dl-tool/main.go              # humacli wiring only: config, store, router, workers
├── internal/                        # never `pkg/` — nothing here is a public API
│   ├── config/                      # DLTOOL_* env parsing and boot validation
│   ├── store/                       # all SQL: sqlx access, row structs, retention
│   │   └── migrations/              # goose .sql files, //go:embed-ed
│   ├── api/                         # chi router, Huma operations, middleware, SPA, SSE
│   ├── compat/                      # qBittorrent /api/v2 and Synology /webapi façades
│   ├── engine/                      # Engine interface, adapter registry, URI→engine router
│   │   ├── aria2/                   # aria2 JSON-RPC client and field/status mapping
│   │   ├── qbittorrent/             # qBittorrent WebAPI v2 client and field/status mapping
│   │   ├── ytdlp/                   # yt-dlp subprocess runner and stdout JSON parser
│   │   └── enginetest/              # one shared adapter conformance suite
│   ├── uri/                         # URI normalisation, obfuscated schemes, magnet, metainfo
│   ├── search/                      # Torznab client, dlsearch engines, .dlm import
│   ├── rss/                         # feed polling, parsing, rule matching, episode filters
│   ├── jobs/                        # worker pool, cron, extract/move/notify handlers
│   ├── sync/                        # SSE hub, rid delta computation, event ring buffer
│   ├── fsx/                         # destination browsing, path jail, moves, free space
│   ├── secure/                      # SSRF guard, argon2id hashing, sessions, CSRF
│   └── obs/                         # slog setup, Prometheus registry, health handlers
├── web/                             # Vite SPA (src/api, src/components, src/store, src/locales, e2e)
```

Placement: Go tests sit beside their source as `*_test.go` with fixtures in a sibling `testdata/`; frontend
tests as `*.test.tsx` beside the component, Playwright specs in `web/e2e/`. Code shared by two packages lives
in the package owning the concept, never in a new `common/` or `util/` package.

## 2. Go conventions

### 2.1 Packages and files

| Rule | Value |
|---|---|
| Module and language | `github.com/L-K-M/dl-tool`, Go 1.26, `CGO_ENABLED=0` for `make build` |
| Package name | Short, lower case, no underscores, no plural: `store`, `engine`, `fsx`, `secure` |
| Directory tree | `internal/` only; `pkg/` is forbidden |
| File name | `snake_case.go` matching its subject: `handlers_extract.go`, `dlm_import.go` |
| Import grouping | stdlib, blank line, third party, blank line, `github.com/L-K-M/dl-tool/...` |

Every exported symbol — type, function, method, constant, variable — carries a doc comment starting with the
symbol's own name. An exported symbol with no doc comment fails `make lint`.

### 2.2 Error model

Each package declares its sentinel errors at the top of its primary file. Two spellings are repository-wide
vocabulary and every package that can express them uses exactly these names:

| Sentinel | Meaning |
|---|---|
| `ErrNotFound` | The addressed row, task or path does not exist. |
| `ErrNotSupported` | The operation is valid but this implementation lacks the capability; nothing was mutated. |

```go
// ErrNotFound is returned when no task with the given id exists.
var ErrNotFound = errors.New("store: task not found")

err := s.db.GetContext(ctx, &t, `SELECT id, state, engine, engine_ref FROM tasks WHERE id = ?`, id)
if errors.Is(err, sql.ErrNoRows) {
	return Task{}, fmt.Errorf("task %s: %w", id, ErrNotFound) // caller matches with errors.Is
} else if err != nil {
	return Task{}, fmt.Errorf("select task %s: %w", id, err)
}
```

- Wrap every error crossing a package boundary with `fmt.Errorf("<what failed>: %w", err)`; never `%v`.
- Compare with `errors.Is` / `errors.As`, never against error strings.
- Never discard an error with `_ = err` and never add `//nolint`. Handle it or wrap it.
- Error text is lower case, has no trailing punctuation, and contains no secret, token or password.
- Translation of sentinels into `application/problem+json` lives in `internal/api/errors.go`; the wire shapes
  are in [`05-api-contract.md`](05-api-contract.md).

### 2.3 Signatures

- `ctx context.Context` is the first parameter of every function that performs I/O and is never stored in a
  struct field; `error` is the last return value.
- No naked returns: name results only for documentation, and always return values explicitly.
- Accept interfaces, return concrete structs; constructors are `New<Type>(...) (*Type, error)`. A goroutine
  is owned by the component that starts it and stops when that component's context is cancelled.

### 2.4 SQL and sqlx

- The query layer is `github.com/jmoiron/sqlx v1.4.0` over `modernc.org/sqlite v1.57.0` (driver name
  `"sqlite"`). No ORM, no query builder.
- **IMPORTANT** Always write an explicit column list. `SELECT *` is forbidden: a later migration that adds a
  column silently breaks every `StructScan` target.
- Row structs live in `internal/store/models.go` with both `db:"..."` and `json:"..."` tags. Scan with
  `StructScan`, `GetContext` or `SelectContext`, never positional `Scan`.
- Bind with `?` placeholders or `sqlx.Named` — string concatenation into SQL is forbidden — and give every
  statement a context: `ExecContext`, `GetContext`, `SelectContext`, `QueryxContext`.
- Multi-statement writes run in one `sqlx.Tx` with `defer tx.Rollback()` placed before the commit.

## 3. Logging

Logging is stdlib `log/slog` only — no zerolog, no zap, no `fmt.Println`, no `log.Printf`.

```go
// internal/obs/log.go — DLTOOL_LOG_FORMAT picks the handler, DLTOOL_LOG_LEVEL the level; both in doc 11.
var h slog.Handler = slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{Level: lvl}) // "json", production
if cfg.LogFormat == "text" {
	h = tint.NewHandler(os.Stdout, &tint.Options{Level: lvl}) // development only
}
slog.SetDefault(slog.New(h))
```

### 3.1 Standard attribute keys

Use these exact keys. The API middleware puts a request-scoped `*slog.Logger` on the context; handlers take
it from there instead of inventing new key names for the same concept.

| Key | Value | Present on |
|---|---|---|
| `request_id` | string | Every record produced during an HTTP request |
| `task_id` | `tsk_…` | Every record about one task, including engine calls and jobs |
| `engine` | `aria2` \| `qbittorrent` \| `ytdlp` | Every engine call, poll and conformance check |
| `user_id` | `usr_…` | Every authenticated request and every ownership decision |

### 3.2 Levels

- `debug` — wire-level detail: engine request and response summaries, rid delta sizes. Off by default.
- `info` — normal operator-visible facts: boot, migrations applied, state transitions, job outcomes.
- `warn` — degraded but handled: engine unreachable and retrying, SSRF-blocked fetch, conformance drift.
- `error` — the operation failed and a user-visible thing did not happen.

### 3.3 Secrets

Never log a password, API token, session cookie, engine secret, extraction password, or an `Authorization`,
`Cookie` or `X-Api-Key` header — at any level, `debug` included. Log a URL only after stripping userinfo and
query secrets; redaction rules and the `"__redacted__"` placeholder are in doc 11.

## 4. The `task_events` code vocabulary

`task_events.code` is a stable, machine-readable, dotted identifier; the UI translates it through i18next and
falls back to the row's `message`. The column and its DDL are owned by
[`04-data-model.md`](04-data-model.md).

Naming rule: `<area>.<subject>[.<outcome>]`, lower case, ASCII letters, digits and dots only, words inside a
segment joined without separators. The last segment is a past-tense outcome — `accepted`, `started`,
`failed`, `blocked`, `paused` — wherever an outcome exists.

| Area prefix | Emitted by | Examples |
|---|---|---|
| `task.` | Task lifecycle in `internal/api` and `internal/store` | `task.created`, `task.removed` |
| `engine.` | Adapters and the router in `internal/engine` | `engine.accepted` |
| `postprocess.` | Job handlers in `internal/jobs` | `postprocess.extract.failed` |

1. Declare the constant next to the emitting code and add the matching i18next key to
   `web/src/locales/en/<namespace>.json` in the same commit.
2. Never rename or reuse a code; a rename orphans stored history rows. Add a new one, stop emitting the old.
3. Never put a variable value in a code; values go in `task_events.detail_json` and the translation
   interpolates them. A code is not an error code — `tasks.error_code` is a separate closed enum in doc 04.

## 5. Frontend conventions

| Concern | Rule |
|---|---|
| Component file | `PascalCase.tsx`, one component per file, in `web/src/components/<Area>/` |
| Hook file | `useThing.ts`, one hook per file, named export |
| Other module | `camelCase.ts`; shadcn copy-ins keep their generated `kebab-case.tsx` names under `web/src/components/ui/` |
| Test file | `<Subject>.test.tsx` beside the subject; Playwright specs in `web/e2e/*.spec.ts` |
| Generated API types | `web/src/api/schema.d.ts`, produced from `api/openapi.json` by `make gen`; never hand-edited |
| Typed client | `web/src/api/client.ts` wraps `openapi-fetch` with the base path, credentials and CSRF header |
| Store | `web/src/store/*.ts`, one `zustand` store per domain |

- No component, hook or store calls `fetch`, `axios` or `XMLHttpRequest`. Every request goes through the
  generated `openapi-fetch` client, so a changed path or body fails typecheck instead of failing at runtime.
- The SSE reducer is the only writer of live task state: it merges the `sync` events of
  [`05-api-contract.md`](05-api-contract.md) into the `zustand` store. Components read the store through
  selectors and never subscribe to the event stream themselves.
- Components hold layout and local UI state only; derived values belong in selectors or memoised helpers.
  Every user-visible string goes through `t()` and every byte, rate, duration and date through `Intl`.

## 6. Git conventions

| Item | Format | Example |
|---|---|---|
| Branch | `task/T0NN-<kebab-slug>` | `task/T019-aria2-adapter` |
| Commit subject | `T0NN: <imperative summary>`, ≤ 72 characters, no trailing full stop | `T019: add the aria2 JSON-RPC adapter` |
| Commits per task | Exactly one, carrying the code, the pasted `## Evidence` and the `done` status in the task index | — |

- Never force-push a shared branch — `main`, or any branch with a pull request somebody has reviewed.
  Force-push only your own unreviewed `task/…` branch.
- Never hand-edit a generated artefact: `api/openapi.json` and `web/src/api/schema.d.ts` are committed as the
  output of `make gen`. Never commit a secret, a `.env` file, a database file, or anything under `/config`.

## 7. Repository-wide hard rules

These seven are the complete global prohibition list and match [`../AGENTS.md`](../AGENTS.md) exactly.
Task-local prohibitions belong in the task file's `## Out of scope — do NOT` section instead.

1. NEVER modify a file that is not listed in the current task file's `Files` table. If you believe you must,
   STOP and write why under `## Blocked` in that task file.
2. NEVER skip, xfail or delete a test, weaken an assertion, or add `//nolint` / `_ = err` to make a check
   pass. Fix the cause.
3. NEVER add a dependency without an ADR in [`decisions/`](decisions/), and never change a pinned version.
4. NEVER hardcode a path, port, URL or secret. Every one of them is a setting defined in
   [`11-config-reference.md`](11-config-reference.md).
5. NEVER copy a fact between documents. Each fact has exactly one home (see [`00-INDEX.md`](00-INDEX.md));
   link to it.
6. NEVER ship a bundled indexer for a piracy site, and never execute third-party definition code — no PHP,
   no Python plugins, no scripting runtime. See
   [`ADR-0010`](decisions/0010-never-execute-third-party-definitions.md).
7. ALWAYS finish a task by running its `## Verification` block, pasting the real output into that task
   file's `## Evidence` section, and setting its status to `done` in the task index — in the same commit.

## 8. Checklists

### 8.1 Add an engine adapter

1. Create `internal/engine/<name>/client.go` and `internal/engine/<name>/map.go`; the daemon status string →
   `TaskState` table goes in `map.go` and nowhere else.
2. Implement every mandatory method of the `Engine` interface in
   [`06-download-engines.md`](06-download-engines.md); an optional method whose `Capability` is undeclared
   returns `ErrNotSupported` and mutates nothing.
3. Register the adapter with one line in `internal/engine/registry.go`, keyed by `Name()`.
4. Add its URI-scheme rows to `internal/engine/router.go` in evaluation order.
5. Add its env vars to [`11-config-reference.md`](11-config-reference.md) and `.env.example`.
6. Add `internal/engine/<name>/contract_test.go` with `//go:build integration` calling
   `enginetest.RunContract`, plus golden fixtures in `internal/engine/<name>/testdata/`, then run
   `make test-integration`.

### 8.2 Add a `dlsearch/v1` definition kind

1. Extend the `kind` enum and its per-kind required fields in
   [`07-search-and-indexers.md`](07-search-and-indexers.md) first; that schema is authoritative.
2. Add the kind to the loader and validator in `internal/search/definition.go`, with a rejection message
   naming the offending line number.
3. Implement row extraction and field mapping in `internal/search/dlsearch.go`, reusing the existing filter
   pipeline. Add no new template placeholder and no code execution.
4. Normalise output through `internal/search/normalize.go`, then add a golden fixture pair under
   `internal/search/testdata/` and a parser test.
5. Bundle a definition file under `definitions/engines/` only if the plan lists it; imported definitions
   start disabled.

### 8.3 Add a migration

1. Create `internal/store/migrations/000NN_<change>.sql` with the next five-digit number; never edit an
   applied migration.
2. Include both `-- +goose Up` and `-- +goose Down` sections; `Down` is mandatory even when it only drops
   what `Up` created.
3. Update the DDL and the erDiagram in [`04-data-model.md`](04-data-model.md) in the same commit.
4. Update the affected row structs in `internal/store/models.go` and every explicit `SELECT` column list that
   must carry the new column, then run `make test`.
